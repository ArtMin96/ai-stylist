# Module Contract — `shared-kernel`

> Module names are canonical per [SPINE §3](../../planning/SPINE.md). Path: `packages/shared-kernel`. This contract is the module's source of truth; code that contradicts it is wrong until a DEC entry says otherwise.

- **Responsibility (one sentence):** Pure types, constants, and registries shared by every module: ULID prefixes, units and their display conversions, body measurement definitions with their hard bounds, avatar starting shapes, the profile and consent-purpose enums, event envelope type, error/reason/entitlement registries, forbidden log keys, the log and span error-shape rules, the correlation id header and log key, the feature-flag and owners registries, and the ports several modules share (clock, outbox writer, storage, feature flags).
- **Owner:** @ArtMin96 (see `CODEOWNERS`) · **Status:** draft (P03) · **Last updated:** 2026-10-21

## Public interface

Public interface: `index.ts` only, which re-exports every file below in full. The data behind `reason-codes.ts`, `entitlements.ts` and `units.ts` comes from `registry/*.json` (JSON Schema-validated) through the generated `src/gen/*.ts`; the same registries generate the Swift `AIStylistKernel` target and the Kotlin `app.aistylist.contracts.kernel` package (`just generate`, [ADR-0005](../adr/0005-shared-kernel-registries-for-native-clients.md)). Edit the JSON, never `src/gen`. `forbidden-log-keys.ts`, `log-redaction.ts`, `correlation.ts`, `owners.ts`, `feature-flags.ts`, `measurements.ts` and `starting-shapes.ts` import `registry/forbidden-log-keys.json`, `registry/log-redaction.json`, `registry/correlation.json`, `registry/owners.json`, `registry/feature-flags.json`, `registry/measurement-definitions.json` and `registry/starting-shapes.json` directly (no generated TS, no Swift/Kotlin; P03-X04 emits the measurement definitions for Swift and Kotlin, so the apps check bounds on the device with the same numbers the server uses). `profile-enums.ts`, `consent-purposes.ts` and the grant kinds and lifecycle states of `entitlements.ts` are TS `as const` lists; the native apps get them through the OpenAPI enums of P03-T02, which are tested against these lists. Each `level` entitlement in `registry/entitlements.json` lists its `levels`, lowest first. They reach TS through the generated `ENTITLEMENTS`, but not Swift or Kotlin yet: the kernel emitters write only each name's `kind` and `description`. For the Python workers, `just generate` (`gen-kernel.mjs python`, called by `tools/codegen/gen-python.sh`) emits `forbidden-log-keys`, its examples, `log-redaction` and `correlation` (joined with the event envelope's `correlationId` rule from `packages/contracts/events/envelope.json`) as the package `ai_stylist_generated.kernel` in `workers/ml/generated` (DEC-55 extended; `packages/contracts/tests/kernel-python.test.ts` imports it with a real Python interpreter and pins every value and vector verdict to the JSON). Other non-TS readers (lint rules, the expired-flag report, `gen-kernel.mjs`) resolve those JSON files through the package export `@ai-stylist/shared-kernel/registry/*` (`createRequire(import.meta.url).resolve('@ai-stylist/shared-kernel/registry/<file>.json')`; the package ships `registry/` in `files`, so `pnpm pack` includes it). `tools/observability` still reads them relative to the repository root it syncs from (its tests stage a copy of that tree). `registry/forbidden-log-keys.examples.json` holds the word-split examples for that list: `forbidden` keys (camel, snake, kebab and UPPER variants) every matcher must treat as forbidden, and `allowed` keys (the doc 14 §2 required ids and near-misses such as `latency` or `tokenizerVersion`) it must not. A key is forbidden when the whole key, or any of its words, is a registry word. TS tests import `FORBIDDEN_LOG_KEY_EXAMPLES` and Python tests the generated `FORBIDDEN_LOG_KEY_EXAMPLES_FORBIDDEN` / `_ALLOWED`; any other matcher of the list (such as the forbidden-field lint) must be tested against this same file, never a copy. `registry/log-redaction.json` holds the error-shape rules every logger and span sanitizer applies (doc 11 §8, doc 14 §2–3): `errorNameShape` (an error class name kept in a log `err.type` or a span `exception.type`, else `Error`), `codeShape` (a SQLSTATE or system code kept in `err.code` or `exception.type`), `maxCauseDepth` (cause links followed, 5) and `nestContextShape` (a Nest logger `context` kept only when it is a PascalCase class name, else redacted), plus `vectors`: `exceptionType.kept` / `.replaced` and `nestContext.kept` / `.redacted`. Each shape is an anchored, ASCII-only regex source that compiles unchanged in JavaScript (no flags) and Python (`re.ASCII`, full match). TS code imports `LOG_REDACTION_RULES` (compiled, frozen `RegExp`s and the depth) and its tests `LOG_REDACTION_EXAMPLES`; Python code imports the generated `ERROR_NAME_SHAPE`, `CODE_SHAPE`, `NEST_CONTEXT_SHAPE` (compiled with `re.ASCII`; always `fullmatch`) and `MAX_CAUSE_DEPTH`, and its tests the vectors `EXCEPTION_TYPE_KEPT` / `_REPLACED` and `NEST_CONTEXT_KEPT` / `_REDACTED`, from `ai_stylist_generated.kernel` (until the worker switches, it keeps hand constants pinned to the JSON by its tests). `registry/correlation.json` holds the names every hop carries the correlation id under (doc 14 §2): `header` (`x-correlation-id`) and `logKey` (`correlation_id`, also the span attribute), plus `vectors.accepted` / `.rejected`, the labelled ids every check of the envelope's `correlationId` rule is tested against (the envelope schema in `packages/contracts/tests/events.test.ts`, the API header check, the worker header check). Which ids are valid stays in the envelope schema and is never restated here; `gen-kernel.mjs` fails unless that pattern is anchored and printable ASCII, so the worker's `re.ASCII` `fullmatch` reads it as Ajv does. TS code imports `CORRELATION_ID_HEADER`, `CORRELATION_ID_KEY` and, in tests, `CORRELATION_ID_EXAMPLES`; Python code the generated `CORRELATION_ID_HEADER`, `CORRELATION_ID_KEY`, `CORRELATION_ID_PATTERN`, `CORRELATION_ID_MIN_LENGTH`, `CORRELATION_ID_MAX_LENGTH` and the vectors `CORRELATION_ID_ACCEPTED` / `_REJECTED`. Their schemas are checked by `packages/contracts/tests/kernel-registries.test.ts`, and the cross-references by `tests/feature-flags.test.ts`, `tests/forbidden-log-keys.test.ts` (every `forbidden` example matches a registry word, no `allowed` one does) and `tests/log-redaction.test.ts` (every vector matches its shape as labelled). Everything is importable by every module; nothing here may import anything back (`shared-kernel-pure`; the only dependency is `ulid`).

## Owned data

None: types and constants only, no tables, ever (SPINE §3). No schema file will ever exist here.

## Invariants

1. No business rule lives in a controller, Drizzle schema file, pg-boss job handler, provider wrapper, or React component (doc 04 §4.2 rule 9); adapters translate, this module decides.
2. No tables, no I/O, no framework imports; every export is a type, constant, registry entry, or pure function with a test.
3. Registry data has one source, `registry/*.json`: TS, Swift and Kotlin are generated from the native registries, Python from `forbidden-log-keys`, its examples, `log-redaction` and `correlation`, and `just generate --check` fails when any output is stale. In TS, `forbidden-log-keys` and its `forbidden-log-keys.examples`, `log-redaction`, `correlation`, `owners`, `feature-flags`, `measurement-definitions` and `starting-shapes` are imported as JSON, not generated. Consumers read the same file (directly or through the package export `./registry/*`) or its generated output and never copy the values.
4. Every feature flag names a person id from `registry/owners.json` as owner, declares a safe `offBehavior` and `defaultWhenUnavailable`, and has `expiresAt` unless it is a `kill-switch`; a `rollout` flag expires at most 90 days after `createdAt` (doc 14 §11, NFR-OBS-080). Every role member is a declared person (`tests/feature-flags.test.ts`).
5. Error-shape redaction has one source, `registry/log-redaction.json`: a logged or exported error class name, code or Nest logger context that fails its shape is replaced, never written, and at most `maxCauseDepth` cause links are followed. Every implementation (API logger and span sanitizer, worker redaction and tracing) is tested against the file's `vectors`, never a copy; loosening a shape, raising the depth or removing a vector needs a security-privacy review (`tests/log-redaction.test.ts`).
6. Port tokens are registry symbols (`Symbol.for('ai-stylist.<name>')`) and ports carry no implementation: the storage request checks are pure functions over their arguments (`tests/ports.test.ts`).
7. Measurements are stored in SI (`cm`, `kg`); `convert` is for display only and never changes the stored value. Metric → imperial → metric (and the reverse, incl. feet + inches) round-trips within 1e-9 relative to max(1, |x|); 5′10″ is 177.8 cm (`tests/registries.test.ts`, fast-check).
8. Every measurement definition names its dimension, its dimension's canonical unit and inclusive hard bounds with `min < max` (`registry/measurement-definitions.json`, owner decision 2026-10-13). `checkMeasurementBounds` accepts a value iff it is finite and within the bounds, refuses below and above alike, never clamps, never throws, and its result never carries the value (doc 11 §8). Outside the hard bounds a value is refused and never stored (doc 07 §3.3 severity 1); a conditional range, stored only with the person's confirmation (doc 03 §2.1), is not registered yet (`tests/measurements.test.ts`, fast-check).
9. The starting-shape registry ties every shape to one base mesh (`anny-adult-v1`) and its `default` is a registered shape (`from_measurements`). The enums of `profile-enums.ts` and `consent-purposes.ts` hold exactly the values decided on 2026-10-13; no pronoun field exists. Every id and enum value is stable: once in the OpenAPI, removing or renaming one is a breaking change (`tests/registries.test.ts`).
10. Each `level` entitlement lists two or more distinct levels, lowest first, and no other kind lists any (`registry/entitlements.schema.json`). `compareEntitlementLevels` orders two levels of one entitlement by that list. Levels, grant kinds and lifecycle states are wire values of `GET /v1/me/entitlements`, never renamed or reused (`tests/registries.test.ts`).

## Dependencies (allowed)

- Nothing (`shared-kernel-pure`, doc 04 §4.2 rule 6): no workspace package, no framework, no I/O. Every module and `platform` may import it.
- Ports: may host port interfaces shared by several modules (doc 04 §4.2 rule 4); never their implementations. Hosted today: `Clock` + `CLOCK`, `OutboxWriter` + `OUTBOX_WRITER`, `StorageProvider` + `STORAGE_PROVIDER` (with its pure request checks) in `src/ports/`, and `FeatureFlags` + `FEATURE_FLAGS`. Adapters live in `platform`, module-test fakes in `packages/test-support`. Every token is `Symbol.for('ai-stylist.<name>')`, so two installed copies of the package share one token. A port that needs a contracts type (e.g. `HEALTH_PROBE`, which returns `HealthCheckStatus`) cannot live here (`shared-kernel-pure`) and stays with its consumer. Domain-capability ports used by one module (weather, push, billing provider) belong in that module's `index.ts`, not here.

## Forbidden dependencies

Derived from P02 brief §5 and doc 04 §4.2; every rule has a failing fixture (`just arch-check --fixtures`, which also fails when a rule has none), and exceptions need an ADR.

- Any edge that closes a cycle (`no-cycles`); the graph must equal doc 04 §4.1.
- `apps/api/src/modules/**`, `apps/api/src/platform/**`, `packages/contracts`, and every other workspace package.
- Provider SDKs — `pg-boss`, aws-sdk/R2, RevenueCat, fal.ai, Open-Meteo, FCM, PostHog SDKs (`domain-no-provider-sdk`); ports only.
- Creating `utils/`, `helpers/`, or `common/` directories (`no-utils-dirs`); importing `prototype/**` (`prototype-unimportable`).
- Must not import any workspace package, NestJS, Drizzle, Node I/O, or provider SDK; pure functions only.
- Single-writer path (CLAUDE.md, Parallel sessions): sequence changes, never parallelize them; owner `@ArtMin96` in `CODEOWNERS`.

## Tests

- Location: `packages/shared-kernel/tests/` (single-writer package)
- Required levels: unit + property-based (fast-check) tests for every pure function and registry (P02-T03 ships these with the package); no integration tier — there is no I/O to integrate.
- Fixtures/builders: `packages/test-support/` and `packages/seed-data/` factories; never duplicated across modules; synthetic data only.

## Extension points

- New reason codes, entitlement names, units, or ID prefixes are added to the existing registries with tests; consumers regenerate/import, never copy (`just generate` for contract-facing values). A new level of a `level` entitlement goes into its `levels` at its rank.
- A new feature flag is an entry in `registry/feature-flags.json`. A new person or role is an entry in `registry/owners.json`. Neither needs a code change. A new forbidden log word is an entry in `registry/forbidden-log-keys.json`, and every logger and lint that reads the file picks it up. A new word-split example is an entry under `forbidden` or `allowed` in `registry/forbidden-log-keys.examples.json`, and every matcher's tests that read the file check it. A new error-shape test vector is an entry under `vectors` in `registry/log-redaction.json`. A new correlation id test vector is an entry under `vectors` in `registry/correlation.json`. A new error code is an entry in `ERROR_CODES` (`errors.ts`; additive, the OpenAPI `ProblemDetails.code` is a pattern, not an enum).
- A new measurement definition is an entry in `registry/measurement-definitions.json`, and a new starting shape an entry in `registry/starting-shapes.json`; their tests pin the decided values, so each addition updates them. A conditional plausibility range (the confirmation level of doc 03 §2.1) joins the measurement registry as an additive schema change. A new enum value is an entry in its list in `profile-enums.ts` or `consent-purposes.ts`; `MATERIALS` moves to the closet taxonomy registry when P06-T01 adopts it.
