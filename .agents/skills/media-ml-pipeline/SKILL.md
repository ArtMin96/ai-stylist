# Media / ML Pipeline Development

## Trigger

- Changes to the `media` state machine's pipeline steps, a pg-boss job handler, a `workers/ml/<service>/` endpoint, a provider call (fal.ai, etc.), derived-asset generation, caching/lineage, or an eval suite.
- Not this skill: choosing a model/provider in the first place (ADR + `planning/10-ai-usage-cost-and-evaluation.md` first); on-device ML (`ios-feature` / `android-feature`); 3D asset formats and render output (client-side 3D is deferred (no owner until it resumes)); dashboards/alerts on pipeline metrics once they are emitted (`observability-analytics`).

## Required reading

1. `planning/07-3d-avatar-and-garment-pipeline.md` — stages, states, lineage/provenance; `planning/10-ai-usage-cost-and-evaluation.md` — AI-use classification, cost budget, cache policy, fallback, eval requirements, approved-provider list.
2. `docs/modules/media.md`; `planning/04-architecture.md` §9 (outbox → pg-boss semantics, idempotency, retry, DLQ).
3. `packages/contracts/events/` and worker request/response schemas; `workers/ml/generated/` Pydantic mirrors are generated by `just generate` — never hand-edit.
4. `workers/ml/segmentation/` (echo stub, Dockerfile, `pyproject` + `uv.lock`) — house style for a worker.
5. `apps/api/src/jobs/README.md` — the job composition root is a P02-T08 placeholder today (no `index.ts` yet, no `pg-boss` dependency); read this file, not an assumption, for the current state before touching a job handler.

## Workflow

1. Restate: stages touched, cost per invocation, expected volume, and the deterministic alternative considered. Deterministic before AI (CLAUDE.md): a new model call needs the doc 10 entry (schema, why not deterministic, cost/latency budget, cache key, fallback, eval).
2. Search before write: an equivalent derivation or task may exist; check lineage kinds already recorded and the job composition root under `apps/api/src/jobs/` (`apps/api/src/jobs/README.md` says what exists there today).
3. This seam splits across three agents in order — do not let one agent silently absorb another's part: `api-engineer` owns the `media` module's public application service and state machine (`apps/api/src/modules/media/`), `platform-engineer` owns the pg-boss job handler and composition root (`apps/api/src/jobs/`, `apps/api/src/platform/`), `ml-engineer` owns the Python worker (`workers/ml/<service>/`). A task that touches more than one of these hands off between agents rather than reaching across the boundary itself.
4. Invariants: jobs idempotent on input hash + step version (idempotency-keys table); cache before call and store lineage (source asset, model + version, params, cost, confidence); provenance marker + confidence on every generated asset; a real photo is never overwritten; bounded retries with backoff, DLQ state, and a user-visible failed/retry state; EXIF stripped at ingest; face/body media only to approved providers; no sensitive data in logs or payload dumps.
5. Job handlers are thin (the composition root under `apps/api/src/jobs/` imports public services only — see required-reading item 5); provider SDKs stay in `apps/api/src/platform/` or the worker, never in `modules/**`.
6. API ↔ worker boundary: versioned JSON schemas on both sides; bump on shape change, accept the previous version during rollout.
7. Model/prompt changes are versioned and recorded in lineage. Python: Ruff + Pyright clean via `just lint` / `just typecheck`, deps via `uv`, `uv.lock` committed.
8. Tests: state-machine + idempotency/retry/cancel tests in `apps/api/src/modules/media/tests/`; pytest/hypothesis in `workers/ml/<service>/tests/`; Schemathesis against the worker OpenAPI.

## Validation commands

```bash
just test media                      # media module's state-machine + idempotency tests
just test workers                    # the workers/ uv workspace's pytest suite (all services)
just ml-eval                         # stub in P02; suite selection: OPEN until T17 defines it
just lint && just typecheck && just generate --check && just arch-check
just dev-workers                     # segmentation worker on :8001; report the actual outcome
```

Report eval metrics and estimated cost delta per 1k items as before → after real numbers.

## Output

- PR with pipeline diff, lineage/version notes, eval output, cost delta, and the doc 10 entry for any new AI call.

Done checklist: idempotency + retry tests green · provenance fields set · provider on approved list · no sensitive data in logs/fixtures · `uv.lock` updated if deps changed · `PROGRESS.md` updated.

## Stop / escalation

- Eval below the doc 10 threshold or cost above budget → stop; shipping behind a gate is a human decision.
- Provider not on the doc 10/11 approved list → stop; security/privacy review first.
- Reprocessing would destroy user corrections → stop; corrections survive model upgrades (doc 07).
- A task needs the `media` module's public service, the job handler, and the worker all changed at once → follow the agent order in Workflow step 3; do not have one agent write another's file set.
