# Module Contract — `platform`

> Module names are canonical per [SPINE §3](../../planning/SPINE.md). Path: `apps/api/src/platform`. This contract is the module's source of truth; code that contradicts it is wrong until a DEC entry says otherwise.

- **Responsibility (one sentence):** Infrastructure adapters that implement the ports declared by domain modules: storage (R2), durable jobs (pg-boss), outbox relay, logger, OTel init, PostHog server, resilience utilities, provider SDK wrappers; deployment target is owned servers + Coolify (DEC-42).
- **Owner:** @team (placeholder — see `CODEOWNERS`) · **Status:** draft · **Last updated:** 2026-09-27

## Invariants

1. Adapters translate only: no business rule lives in any adapter, task body, or provider wrapper (doc 04 §4.2 rule 9).
2. This module writes only the tables it owns (doc 04 §4.2 rule 8); cross-module behaviour goes through public application services or events.
3. Presigned URLs are short-lived (doc 11 §5.4): GET (read) TTL is clamped to ≤ 10 minutes (`MAX_PRESIGN_GET_TTL_SECONDS`), PUT/multipart (write) TTL to ≤ 15 minutes (`MAX_PRESIGN_PUT_TTL_SECONDS`); asserted in `apps/api/src/platform/tests/storage.port.test.ts`.
4. The outbox relay claims at most 100 rows per poll (`MAX_OUTBOX_BATCH_SIZE`; a larger `batchSize` is rejected), and concurrent relays never claim the same row (`FOR UPDATE SKIP LOCKED`). Proven by `outbox-relay.test.ts` ("rejects a batch above 100 …"), `outbox-relay.docker.test.ts` ("two relays on one table … never > 100 per poll") and AC-5 in `apps/api/src/jobs/tests/acceptance-dispatch.docker.test.ts`.
5. No payload or foreign error text is stored or logged: `last_error` holds the error class plus `(pg <SQLSTATE>)` (the message only for the relay's own errors), a failed job's pg-boss `output` is `{ errorName, pgCode? }`, and logs carry ids, queue, attempt and error class only. Proven by `outbox-relay.test.ts` (`describeSendError`), `outbox-relay.docker.test.ts` ("never stores or logs a send error message that echoes the payload …"), `queue.docker.test.ts` ("fails a job after exactly retryLimit retries and dead-letters it": stored output has no payload marker) and AC-2 in `acceptance-dispatch.docker.test.ts`.
6. One job per idempotency key: the job id is the UUIDv5 of the key (the outbox event id), so a repeated `send()` or relay re-dispatch inserts nothing. Proven by `queue.docker.test.ts` ("enqueues exactly one job when the same idempotency key is sent twice"), `outbox-relay.docker.test.ts` ("… exactly one job keyed by the event id, also on re-dispatch") and AC-1.
7. A guarded side effect runs at most once per key for its retention, durably: `PgIdempotencyGuard` records the key only with a completed effect, and a thrown effect leaves no key. Proven by `idempotency.docker.test.ts` and AC-3 (replay after pg-boss dropped the job makes no second worker call).
8. No pg-boss DDL runs on boot: pg-boss starts with `migrate: false` and `start()` refuses an unmigrated database; migration 0003 must equal the installed pg-boss's construction plan. Proven by `queue.docker.test.ts` ("refuses to start before `just db-migrate` installed the pg-boss schema") and `apps/api/tests/migrations/pgboss-schema.test.ts`.
9. A dead-lettered job marks its outbox row `failed` (idempotently, first reason kept), and the relay never re-dispatches a `failed` row. Proven by `outbox-dead-letter.docker.test.ts` and AC-2 in `acceptance-dispatch.docker.test.ts`.
10. After `cancelUser(userId)` resolves, no job keyed to that user reaches a handler on any instance for 100 days (`CANCELLED_USER_MARKER_RETENTION_SECONDS`: 90-day outbox replay + 7-day deletion grace + margin): `send` refuses the user and `work` cancels a racing job without calling the handler. Proven by `queue.docker.test.ts` ("keeps a cancelled-user marker 100 days …"), AC-6/AC-7 in `acceptance-lifecycle.docker.test.ts` and `apps/api/src/jobs/tests/batch-settlement.docker.test.ts`.
11. Spans and logs carry ids and enums only (doc 14 §3, doc 11 §8). The platform's own spans (`outbox.dispatch <event type>`, `job.process <queue>`) set ids, enums and `correlation_id` only and record a failure by error class; `SanitizingSpanExporter` strips every exported span of query strings (`url.query`, the query of `url.full` / `url.path`), client IPs, user agents, status messages and exception messages and stack traces, and redacts attributes named with a forbidden log word; OTel log records are the pino lines after the logger's redaction. Proven by `trace-context.test.ts`, `telemetry.process.test.ts` ("… ids only") and `logger.redaction.test.ts` (behind the telemetry entry, no planted value on stdout or in any OTLP body).
12. Without `OTEL_EXPORTER_OTLP_ENDPOINT` the telemetry entries start nothing: no loader hook, no SDK, no exporter, no network; logs still carry `correlation_id`. Proven by `telemetry.process.test.ts` ("without an OTLP endpoint nothing starts …").
13. One trace and one correlation id cover API request → outbox → job → worker call (doc 14 §2–§3): `PgOutboxWriter` stores the active span's `traceparent` in an envelope without one, the relay's PRODUCER span and the job's CONSUMER span are parented on it, the job runs in the envelope's correlation scope, and the worker request carries the job's `traceparent` (undici) and `x-correlation-id`. An inbound `x-correlation-id` is accepted only as 1–128 chars of `[A-Za-z0-9._:-]`, else minted. Proven by `apps/api/src/jobs/tests/trace-propagation.docker.test.ts` (P02-T09 AC-1) and `correlation.test.ts`.

## Dependencies (allowed)

- `packages/shared-kernel`, `packages/contracts` (generated types only) and provider SDKs (`pg-boss`, `postgres`, `pino`, the OpenTelemetry SDK, exporters and instrumentations, `@fastify/otel`, …) only (`platform-leaf`, doc 04 §4.2 rule 5). Domain modules may use `@opentelemetry/api` only (`domain-no-provider-sdk`). Adapters are bound to ports at `apps/api/src/main.ts` / `app.module.ts` and `apps/api/src/jobs/index.ts`.
- Ports: implements ports declared by modules. P02-interim exception: four port tokens still live in `apps/api/src/platform/ports/` (`CLOCK`, `HEALTH_PROBE`, `STORAGE_PROVIDER`, `OUTBOX_WRITER`); each moves to `packages/shared-kernel` before the first domain module injects it (`OUTBOX_WRITER` before the first module producer; `tools/depcruise/README.md`). Fakes for tests live in `packages/test-support/`.

## Forbidden dependencies

Derived from P02 brief §5 and doc 04 §4.2; every rule has a failing fixture in `just arch-check`, and exceptions need an ADR.

- Any edge that closes a cycle (`no-cycles`); the graph must equal doc 04 §4.1.
- `apps/api/src/modules/**` entirely — public API included (`platform-leaf`); `apps/api/src/jobs/**` too (queue names and routing are injected by the composition root).
- (Provider SDKs are allowed here — this is the only place they may be imported, besides the `jobs/` composition root; `domain-no-provider-sdk` bans `pg-boss` in modules.)
- Creating `utils/`, `helpers/`, or `common/` directories (`no-utils-dirs`); importing `prototype/**` (`prototype-unimportable`).
- Logger: allowlist serialization + forbidden-key denylist (doc 11 §8); `console.*` and raw `req.body` logging are lint errors (P02 §6).

- Observability (P02-T09): `telemetry.process.test.ts` runs the `--import` entries in a tsx child process against a stub OTLP receiver; `logger.redaction.test.ts` is the redaction canary (in process and behind the entry); `trace-context.test.ts` and `correlation.test.ts` use an in-process SDK with an in-memory exporter; `apps/api/src/jobs/tests/trace-propagation.docker.test.ts` is AC-1 (one trace, one correlation id, outbox append → worker request; `just test api`).
- Required levels: unit for invariants/rules · contract tests for the public interface and events · integration (Testcontainers Postgres + pgvector) for every adapter over Postgres or pg-boss.
- Fixtures/builders: `packages/test-support/` and `packages/seed-data/` factories; never duplicated across modules; synthetic data only.

## Extension points

- New provider = new adapter implementing an existing port + fake in `packages/test-support/`; never a new import path into domain modules.
- New job consumer = a `QueueDefinition` and an event-type route in `apps/api/src/jobs/queues.ts` (plus its worked DLQ) and a handler registered in `apps/api/src/jobs/index.ts`; nothing in `platform` changes.
