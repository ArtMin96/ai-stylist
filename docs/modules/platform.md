# Module Contract — `platform`

> Module names are canonical per [SPINE §3](../../planning/SPINE.md). Path: `apps/api/src/platform`. This contract is the module's source of truth; code that contradicts it is wrong until a DEC entry says otherwise.

- **Responsibility (one sentence):** Infrastructure adapters that implement the ports declared by domain modules: storage (R2), durable jobs (pg-boss), outbox relay, logger, OTel init, PostHog server, resilience utilities, provider SDK wrappers; deployment target is owned servers + Coolify (DEC-42).

## Invariants

1. Adapters translate only: no business rule lives in any adapter, task body, or provider wrapper (doc 04 §4.2 rule 9).
2. This module writes only the tables it owns (doc 04 §4.2 rule 8); cross-module behaviour goes through public application services or events.
3. Presigned URLs are short-lived (doc 11 §5.4): GET (read) TTL is clamped to ≤ 10 minutes (`MAX_PRESIGN_GET_TTL_SECONDS`), PUT/multipart (write) TTL to ≤ 15 minutes (`MAX_PRESIGN_PUT_TTL_SECONDS`), and a TTL under 1 second is refused; `expiresAt` is never later than the URL's real expiry. Asserted in `apps/api/src/platform/tests/storage.port.test.ts` and, for R2 URLs (`X-Amz-Expires`, an expired PUT and GET refused by a SigV4-verifying endpoint), `r2-storage.sec.test.ts`.
4. The outbox relay claims at most 100 rows per poll (`MAX_OUTBOX_BATCH_SIZE`; a larger `batchSize` is rejected), and concurrent relays never claim the same row (`FOR UPDATE SKIP LOCKED`). Proven by `outbox-relay.test.ts` ("rejects a batch above 100 …"), `outbox-relay.docker.test.ts` ("two relays on one table … never > 100 per poll") and AC-5 in `apps/api/src/jobs/tests/acceptance-dispatch.docker.test.ts`.
5. No payload or foreign error text is stored or logged: `last_error` holds the error class plus `(pg <SQLSTATE>)` (the message only for the relay's own errors), a failed job's pg-boss `output` is `{ errorName, pgCode? }`, and logs carry ids, queue, attempt and error class only. Proven by `outbox-relay.test.ts` (`describeSendError`), `outbox-relay.docker.test.ts` ("never stores or logs a send error message that echoes the payload …"), `queue.docker.test.ts` ("fails a job after exactly retryLimit retries and dead-letters it": stored output has no payload marker) and AC-2 in `acceptance-dispatch.docker.test.ts`.
6. One job per idempotency key: the job id is the UUIDv5 of the key (the outbox event id), so a repeated `send()` or relay re-dispatch inserts nothing. Proven by `queue.docker.test.ts` ("enqueues exactly one job when the same idempotency key is sent twice"), `outbox-relay.docker.test.ts` ("… exactly one job keyed by the event id, also on re-dispatch") and AC-1.
7. A guarded side effect runs at most once per key for its retention, durably: `PgIdempotencyGuard` records the key only with a completed effect, and a thrown effect leaves no key. Proven by `idempotency.docker.test.ts` and AC-3 (replay after pg-boss dropped the job makes no second worker call).
8. No pg-boss DDL runs on boot: pg-boss starts with `migrate: false` and `start()` refuses an unmigrated database; migration 0003 must equal the installed pg-boss's construction plan. Proven by `queue.docker.test.ts` ("refuses to start before `just db-migrate` installed the pg-boss schema") and `apps/api/tests/migrations/pgboss-schema.test.ts`.
9. A dead-lettered job marks its outbox row `failed` (idempotently, first reason kept), and the relay never re-dispatches a `failed` row. Proven by `outbox-dead-letter.docker.test.ts` and AC-2 in `acceptance-dispatch.docker.test.ts`.
10. After `cancelUser(userId)` resolves, no job keyed to that user reaches a handler on any instance for 100 days (`CANCELLED_USER_MARKER_RETENTION_SECONDS`: 90-day outbox replay + 7-day deletion grace + margin): `send` refuses the user and `work` cancels a racing job without calling the handler. Proven by `queue.docker.test.ts` ("keeps a cancelled-user marker 100 days …"), AC-6/AC-7 in `acceptance-lifecycle.docker.test.ts` and `apps/api/src/jobs/tests/batch-settlement.docker.test.ts`.
11. Spans and logs carry ids and enums only (doc 14 §3, doc 11 §8). The platform's own spans (`outbox.dispatch <event type>`, `job.process <queue>`) set ids, enums and `correlation_id` only and record a failure by error class; `SanitizingSpanExporter` strips every exported span of query strings (`url.query`, the query of `url.full` / `url.path`), client IPs, user agents, status messages and exception messages and stack traces, and redacts attributes named with a forbidden log word. That attribute rule (`sanitizeAttributes`) covers the attributes of the span, of every event and of every link (the linked trace id, span id and flags are kept), and the span name and every event name are cut at the first `?` or `#`; `GET`, `outbox.dispatch <event type>` and `job.process <queue>` come out unchanged. OTel log records are the pino lines after the logger's redaction. Not covered: the value under a key that is neither dropped, forbidden nor a URL attribute is not inspected. Proven by `trace-context.test.ts` (with "cuts the query and fragment from a span name …", "… from an event name …" and "sanitises link attributes …"), `telemetry.process.test.ts` ("… ids only") and `logger.redaction.test.ts` (behind the telemetry entry, no planted value on stdout or in any OTLP body).
12. Without `OTEL_EXPORTER_OTLP_ENDPOINT` the telemetry entries start nothing: no loader hook, no SDK, no exporter, no network; logs still carry `correlation_id`. Proven by `telemetry.process.test.ts` ("without an OTLP endpoint nothing starts …").
13. One trace and one correlation id cover API request → outbox → job → worker call (doc 14 §2–§3): `PgOutboxWriter` stores the active span's `traceparent` in an envelope without one, the relay's PRODUCER span and the job's CONSUMER span are parented on it, the job runs in the envelope's correlation scope, and the worker request carries the job's `traceparent` (undici) and `x-correlation-id`. An inbound `x-correlation-id` is accepted only as 1–128 chars of `[A-Za-z0-9._:-]`, else minted. Proven by `apps/api/src/jobs/tests/trace-propagation.docker.test.ts` (P02-T09 AC-1) and `correlation.test.ts`.
14. Metrics (planning/14 §4) carry route templates, queue names and enums only: never an id, a raw path or user-derived value. The names are fixed and every `stylist_api_*` / `stylist_queue_*` series and label the Grafana dashboards and alerts query is emitted; `stylist.api.request.duration` is in seconds with explicit buckets; every counter series of a known route or job type starts at 0 when the process starts, so the first dead letter after a restart fires `queue.job.dlq`. Proven by `request-metrics.test.ts`, `queue-metrics.test.ts`, `metrics-catalog.test.ts` and `apps/api/src/jobs/tests/queue-metrics.docker.test.ts` (an injected failure through retry → DLQ moves `stylist.queue.job.dlq` from 0 to 1).
15. Feature flags never capture: `PostHogFeatureFlags` sends only `POST <host>/flags/` (one bounded request per 10 s for the fixed system distinct id, no person properties, GeoIP off) and refuses every other request before the network. A flag absent from a clean reply (inactive in PostHog) is off; a timeout, error or quota-limited reply answers the registry's `defaultWhenUnavailable`; `isEnabled` never throws. Proven by `feature-flags.test.ts`.
16. A logged error is an allowlist (doc 11 §8): the `err` serializer, and the logger's walk over an Error under any other key, write `{ type, code?, cause? }` only: the error class (an `Error.name` that is not identifier-shaped, `/^[A-Za-z_$][\w$.]{0,63}$/`, is written as `Error`), a code-shaped `code` (Postgres SQLSTATE or Node system code; both rules are `queue/error-summary.ts`) and the same for at most 5 `cause` links (`MAX_ERR_CAUSE_DEPTH`, not re-exported); a non-Error throw is its `typeof`. Never the message, the stack or a driver field (`detail`, `where`, `hint`, the query or its parameters). `msg` is only the string the caller wrote (`hooks.logMethod`): an error logged without a message gets `error logged` where pino would copy `err.message`, and printf-style arguments and a non-string message are dropped. Child loggers are made with `childLogger(parent, bindings)`, which applies the same rules to the bindings: pino writes raw `.child()` bindings without the log formatter, so only the exact-word redact paths would reach them. Code logs an error under `err`, never a name it computed itself. `ProblemFilter` logs a 5xx as `unhandled error` (context `ProblemFilter`) with that `err`. Proven by `logger.redaction.test.ts` ("keeps err to the error class and SQLSTATE …", "summarises the cause chain …", "logs a thrown non-Error by its type only …", "logs an error name that is not identifier-shaped as Error …", "summarises an Error under any other key …", "redacts child-logger bindings like a logged object …", "never writes error text or interpolation arguments into msg", "through the API error path …", including a Nest `Logger.error(error)` without a message), `error-summary.test.ts` and `feature-flags.test.ts` ("logs a failed client shutdown through the err allowlist …").
17. A URL that platform logs or records is cut at the first `?` or `#` by one function, `stripQuery` in `logger.ts` (not re-exported): the logged `req.url`; the problem `instance`, and the request URL wherever the problem `detail` quotes it (Nest's unknown-route 404, `Cannot GET <url>`) (`ProblemFilter`); the span name and every event name; and the attributes `url.full`, `url.path`, `http.url` and `http.target` wherever `sanitizeAttributes` applies (span, event, link, resource). Such an attribute is cut whatever its shape: the string, or each string of an array value (cut rather than dropped, so the path stays searchable). A query string or a fragment can carry a signed-URL credential, a token or user input, so a new place that writes a URL calls `stripQuery` instead of cutting the string itself. Proven by `logger.redaction.test.ts` ("cuts a logged url at the first ? or # …", "through the API error path …", whose request carries a query and whose problem `instance` is the path, and "answers an unknown route with its path only …") and `trace-context.test.ts` ("strips query strings, network identity and free text …", "cuts every string of an array-valued URL attribute", "cuts the query and fragment from a span name …", "… from an event name …").
18. The process resource is sanitized once, where it is built, never per signal: NodeSDK gives one resource to the trace, metric and log providers, and only spans pass `SanitizingSpanExporter`. `startTelemetry` runs the env detector itself (`OTEL_SERVICE_NAME`, `OTEL_RESOURCE_ATTRIBUTES`; no host or process detector), applies `sanitizeAttributes` to the merged attributes and starts NodeSDK with `autoDetectResources: false`, so no environment value reaches a span, a metric or a log record unsanitized. `service.name`, `service.version`, `deployment.environment.name` (the attributes the dashboards and alerts filter on, as `service_name`, `job` and `deployment_environment_name`) and other attributes without a forbidden word in their last dot-segment pass unchanged; a forbidden one is exported as `[REDACTED]`. Adding a resource detector means adding it inside that step, not to NodeSDK. Proven by `telemetry.process.test.ts` ("sanitises the resource all three signals share …": a value planted in `OTEL_RESOURCE_ATTRIBUTES` is in no OTLP body, the legitimate attributes are in all three) and `trace-context.test.ts` ("sanitises the process resource …").
19. A presigned URL addresses only `<namespace>/<key>` inside its own namespace (`uploads`, `derived`, `avatars`): an unknown namespace and a key that is absolute or has an empty, `.` or `..` segment or any character outside `[A-Za-z0-9._-]` and `/` are refused before signing, by both adapters; the R2 path is signed, so a URL edited to another namespace, key or bucket is refused. Which user's prefix a caller may address is the calling module's authorization (doc 11 §4.3), not this adapter's. Proven by `r2-storage.sec.test.ts` ("refuses keys that could leave the namespace …", "refuses a foreign namespace", "rejects a URL edited to another namespace, key, bucket or a longer expiry").
20. A presigned PUT signs `content-type` (a bare `type/subtype`) and `content-length` (= `sizeLimitBytes`): an upload of another type or of another size, larger or smaller, is refused by the endpoint's signature check. Proven offline by `r2-storage.sec.test.ts` ("rejects an upload of another content type", "rejects a body larger or smaller than the signed size") and against R2 by `r2-storage.live.sec.test.ts`.
21. The storage adapters never log or put into an error message a presigned URL, its query (signature, access key id), the object key, the content type or a credential; the R2 adapter logs `method`, `namespace`, `ttlSeconds` and a `refusal` enum only. Proven by `r2-storage.sec.test.ts` ("… never the URL, its query, the key, the type or a credential", "logs the refusal reason, never the rejected value") and `storage-provider.test.ts`.

## Forbidden dependencies

Derived from P02 brief §5 and doc 04 §4.2; every rule has a failing fixture in `just arch-check`, and exceptions need an ADR.

- Any edge that closes a cycle (`no-cycles`); the graph must equal doc 04 §4.1.
- `apps/api/src/modules/**` entirely — public API included (`platform-leaf`); `apps/api/src/jobs/**` too (queue names and routing are injected by the composition root).
- (Provider SDKs are allowed here — this is the only place they may be imported, besides the `jobs/` composition root; `domain-no-provider-sdk` bans `pg-boss` in modules.)
- Creating `utils/`, `helpers/`, or `common/` directories (`no-utils-dirs`); importing `prototype/**` (`prototype-unimportable`).
- Logger: allowlist serialization + forbidden-key denylist (doc 11 §8); `console.*` and raw `req.body` logging are lint errors (P02 §6). The denylist words have one name, `FORBIDDEN_LOG_KEYS` in `packages/shared-kernel`: import it from there, platform does not re-export it.
