# Media / ML Pipeline Development

## Trigger

- Changes to the `media` state machine, pg-boss jobs, `workers/ml/<service>/` endpoints, provider calls, derived-asset generation, caching/lineage, or eval suites.
- Not this skill: choosing a model/provider (ADR + `planning/10` first); on-device ML (`mobile-feature`); 3D asset formats (`native-3d-assets`).

## Required reading

1. `planning/07-3d-avatar-and-garment-pipeline.md` — stages, states, lineage/provenance; `planning/10-ai-usage-cost-and-evaluation.md` — AI-use classification, cost budget, cache policy, fallback, eval requirements, approved-provider list.
2. `docs/modules/media.md`; `planning/04-architecture.md` §9 (outbox → pg-boss semantics, idempotency, retry, DLQ).
3. `packages/contracts/events/` and worker request/response schemas; `workers/ml/generated/` Pydantic mirrors are generated by `just generate` — never hand-edit.
4. `workers/ml/segmentation/` (echo stub, Dockerfile, `pyproject` + `uv.lock`) — house style for a worker.

## Workflow

1. Restate: stages touched, cost per invocation, expected volume, and the deterministic alternative considered. Deterministic before AI (CLAUDE.md): a new model call needs the doc 10 entry (schema, why not deterministic, cost/latency budget, cache key, fallback, eval).
2. Search before write: an equivalent derivation or task may exist; check lineage kinds and `apps/api/src/jobs/index.ts`.
3. Invariants: jobs idempotent on input hash + step version (idempotency-keys table); cache before call and store lineage (source asset, model + version, params, cost, confidence); provenance marker + confidence on every generated asset; a real photo is never overwritten; bounded retries with backoff, DLQ state, and a user-visible failed/retry state; EXIF stripped at ingest; face/body media only to approved providers; no sensitive data in logs or payload dumps.
4. Job handlers are thin (composition root `apps/api/src/jobs/index.ts` imports public services only); provider SDKs stay in `apps/api/src/platform/` or the worker, never in `modules/**`.
5. API ↔ worker boundary: versioned JSON schemas on both sides; bump on shape change, accept the previous version during rollout.
6. Model/prompt changes are versioned and recorded in lineage. Python: Ruff + Pyright clean, deps via `uv`, `uv.lock` committed.
7. Tests: state-machine + idempotency/retry/cancel tests in `apps/api/src/modules/media/tests/`; pytest/hypothesis in `workers/ml/<service>/tests/`; Schemathesis against the worker OpenAPI.

## Validation commands

```bash
just test media

just ml-eval                         # stub in P02; suite selection: OPEN until T17 defines it
just lint && just typecheck && just generate --check && just arch-check
just dev-workers                     # end-to-end on seed images; report the actual outcome
```

Report eval metrics and estimated cost delta per 1k items as before → after real numbers.

## Output

- PR with pipeline diff, lineage/version notes, eval output, cost delta, and the doc 10 entry for any new AI call.

Done checklist: idempotency + retry tests green · provenance fields set · provider on approved list · no sensitive data in logs/fixtures · `uv.lock` updated if deps changed · `PROGRESS.md` updated.

## Stop / escalation

- Eval below the doc 10 threshold or cost above budget → stop; shipping behind a gate is a human decision.
- Provider not on the doc 10/11 approved list → stop; security/privacy review first.
- Reprocessing would destroy user corrections → stop; corrections survive model upgrades (doc 07).
