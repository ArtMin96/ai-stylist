# Module Contract — `shared-kernel`

> Module names are canonical per [SPINE §3](../../planning/SPINE.md). Path: `packages/shared-kernel`. This contract is the module's source of truth; code that contradicts it is wrong until a DEC entry says otherwise.

- **Responsibility (one sentence):** Pure types, constants, and registries shared by every module: ULID prefixes, units, event envelope type, error/reason/entitlement registries, forbidden log keys, the log and span error-shape rules, the correlation id header and log key, the feature-flag and owners registries, and the ports several modules share (clock, outbox writer, storage, feature flags).
- **Owner:** @ArtMin96 (see `CODEOWNERS`) · **Status:** skeleton (P02) · **Last updated:** 2026-10-13

## Public interface

Public interface: `index.ts` only, which re-exports every file below in full. The data behind `reason-codes.ts`, `entitlements.ts` and `units.ts` comes from `registry/*.json` (JSON Schema-validated) through the generated `src/gen/*.ts`; the same registries generate the Swift `AIStylistKernel` target and the Kotlin `app.aistylist.contracts.kernel` package (`just generate`, [ADR-0005](../adr/0005-shared-kernel-registries-for-native-clients.md)). Edit the JSON, never `src/gen`. `forbidden-log-keys.ts`, `log-redaction.ts`, `correlation.ts`, `owners.ts` and `feature-flags.ts` import `registry/forbidden-log-keys.json`, `registry/log-redaction.json`, `registry/correlation.json`, `registry/owners.json` and `registry/feature-flags.json` directly (no generated TS, no Swift/Kotlin). For the Python workers, `just generate` (`gen-kernel.mjs python`, called by `tools/codegen/gen-python.sh`) emits `forbidden-log-keys`, its examples, `log-redaction` and `correlation` (joined with the event envelope's `correlationId` rule from `packages/contracts/events/envelope.json`) as the package `ai_stylist_generated.kernel` in `workers/ml/generated` (DEC-55 extended; `packages/contracts/tests/kernel-python.test.ts` imports it with a real Python interpreter and pins every value and vector verdict to the JSON). Other non-TS readers (lint rules, the expired-flag report, `gen-kernel.mjs`) resolve those JSON files through the package export `@ai-stylist/shared-kernel/registry/*` (`createRequire(import.meta.url).resolve('@ai-stylist/shared-kernel/registry/<file>.json')`; the package ships `registry/` in `files`, so `pnpm pack` includes it). `tools/observability` still reads them relative to the repository root it syncs from (its tests stage a copy of that tree). `registry/forbidden-log-keys.examples.json` holds the word-split examples for that list: `forbidden` keys (camel, snake, kebab and UPPER variants) every matcher must treat as forbidden, and `allowed` keys (the doc 14 §2 required ids and near-misses such as `latency` or `tokenizerVersion`) it must not. A key is forbidden when the whole key, or any of its words, is a registry word. TS tests import `FORBIDDEN_LOG_KEY_EXAMPLES` and Python tests the generated `FORBIDDEN_LOG_KEY_EXAMPLES_FORBIDDEN` / `_ALLOWED`; any other matcher of the list (such as the forbidden-field lint) must be tested against this same file, never a copy. `registry/log-redaction.json` holds the error-shape rules every logger and span sanitizer applies (doc 11 §8, doc 14 §2–3): `errorNameShape` (an error class name kept in a log `err.type` or a span `exception.type`, else `Error`), `codeShape` (a SQLSTATE or system code kept in `err.code` or `exception.type`), `maxCauseDepth` (cause links followed, 5) and `nestContextShape` (a Nest logger `context` kept only when it is a PascalCase class name, else redacted), plus `vectors`: `exceptionType.kept` / `.replaced` and `nestContext.kept` / `.redacted`. Each shape is an anchored, ASCII-only regex source that compiles unchanged in JavaScript (no flags) and Python (`re.ASCII`, full match). TS code imports `LOG_REDACTION_RULES` (compiled, frozen `RegExp`s and the depth) and its tests `LOG_REDACTION_EXAMPLES`; Python code imports the generated `ERROR_NAME_SHAPE`, `CODE_SHAPE`, `NEST_CONTEXT_SHAPE` (compiled with `re.ASCII`; always `fullmatch`) and `MAX_CAUSE_DEPTH`, and its tests the vectors `EXCEPTION_TYPE_KEPT` / `_REPLACED` and `NEST_CONTEXT_KEPT` / `_REDACTED`, from `ai_stylist_generated.kernel` (until the worker switches, it keeps hand constants pinned to the JSON by its tests). `registry/correlation.json` holds the names every hop carries the correlation id under (doc 14 §2): `header` (`x-correlation-id`) and `logKey` (`correlation_id`, also the span attribute), plus `vectors.accepted` / `.rejected`, the labelled ids every check of the envelope's `correlationId` rule is tested against (the envelope schema in `packages/contracts/tests/events.test.ts`, the API header check, the worker header check). Which ids are valid stays in the envelope schema and is never restated here; `gen-kernel.mjs` fails unless that pattern is anchored and printable ASCII, so the worker's `re.ASCII` `fullmatch` reads it as Ajv does. TS code imports `CORRELATION_ID_HEADER`, `CORRELATION_ID_KEY` and, in tests, `CORRELATION_ID_EXAMPLES`; Python code the generated `CORRELATION_ID_HEADER`, `CORRELATION_ID_KEY`, `CORRELATION_ID_PATTERN`, `CORRELATION_ID_MIN_LENGTH`, `CORRELATION_ID_MAX_LENGTH` and the vectors `CORRELATION_ID_ACCEPTED` / `_REJECTED`. Their schemas are checked by `packages/contracts/tests/kernel-registries.test.ts`, and the cross-references by `tests/feature-flags.test.ts`, `tests/forbidden-log-keys.test.ts` (every `forbidden` example matches a registry word, no `allowed` one does) and `tests/log-redaction.test.ts` (every vector matches its shape as labelled). Everything is importable by every module; nothing here may import anything back (`shared-kernel-pure`; the only dependency is `ulid`).

## Invariants

1. No business rule lives in a controller, Drizzle schema file, pg-boss job handler, provider wrapper, or React component (doc 04 §4.2 rule 9); adapters translate, this module decides.
2. No tables, no I/O, no framework imports; every export is a type, constant, registry entry, or pure function with a test.
3. Registry data has one source, `registry/*.json`: TS, Swift and Kotlin are generated from the native registries, Python from `forbidden-log-keys`, its examples, `log-redaction` and `correlation`, and `just generate --check` fails when any output is stale. In TS, `forbidden-log-keys` and its `forbidden-log-keys.examples`, `log-redaction`, `correlation`, `owners` and `feature-flags` are imported as JSON, not generated. Consumers read the same file (directly or through the package export `./registry/*`) or its generated output and never copy the values.
4. Every feature flag names a person id from `registry/owners.json` as owner, declares a safe `offBehavior` and `defaultWhenUnavailable`, and has `expiresAt` unless it is a `kill-switch`; a `rollout` flag expires at most 90 days after `createdAt` (doc 14 §11, NFR-OBS-080). Every role member is a declared person (`tests/feature-flags.test.ts`).
5. Error-shape redaction has one source, `registry/log-redaction.json`: a logged or exported error class name, code or Nest logger context that fails its shape is replaced, never written, and at most `maxCauseDepth` cause links are followed. Every implementation (API logger and span sanitizer, worker redaction and tracing) is tested against the file's `vectors`, never a copy; loosening a shape, raising the depth or removing a vector needs a security-privacy review (`tests/log-redaction.test.ts`).
6. Port tokens are registry symbols (`Symbol.for('ai-stylist.<name>')`) and ports carry no implementation: the storage request checks are pure functions over their arguments (`tests/ports.test.ts`).
7. Further invariants: OPEN until the first domain phase that touches this module fills them in (each needs at least one test).

## Dependencies (allowed)

- Nothing (`shared-kernel-pure`, doc 04 §4.2 rule 6): no workspace package, no framework, no I/O. Every module and `platform` may import it.
- Ports: may host port interfaces shared by several modules (doc 04 §4.2 rule 4); never their implementations. Hosted today: `Clock` + `CLOCK`, `OutboxWriter` + `OUTBOX_WRITER`, `StorageProvider` + `STORAGE_PROVIDER` (with its pure request checks) in `src/ports/`, and `FeatureFlags` + `FEATURE_FLAGS`. Adapters live in `platform`, module-test fakes in `packages/test-support`. Every token is `Symbol.for('ai-stylist.<name>')`, so two installed copies of the package share one token. A port that needs a contracts type (e.g. `HEALTH_PROBE`, which returns `HealthCheckStatus`) cannot live here (`shared-kernel-pure`) and stays with its consumer. Domain-capability ports used by one module (weather, push, billing provider) belong in that module's `index.ts`, not here.

## Forbidden dependencies

Derived from P02 brief §5 and doc 04 §4.2; every rule has a failing fixture (`just arch-check --fixtures`, which also fails when a rule has none), and exceptions need an ADR.

- Any edge that closes a cycle (`no-cycles`); the graph must equal doc 04 §4.1.
- `apps/api/src/modules/**`, `apps/api/src/platform/**`, `packages/contracts`, and every other workspace package.
- Provider SDKs — `pg-boss`, aws-sdk/R2, RevenueCat, fal.ai, Open-Meteo, FCM, PostHog SDKs (`domain-no-provider-sdk`); ports only.
- Creating `utils/`, `helpers/`, or `common/` directories (`no-utils-dirs`); importing `prototype/**` (`prototype-unimportable`).
- Must not import any workspace package, NestJS, Drizzle, Node I/O, or provider SDK; pure functions only.
- Single-writer path (CLAUDE.md, Parallel sessions): sequence changes, never parallelize them; owner `@ArtMin96` in `CODEOWNERS`.

## Tests

- Location: `packages/shared-kernel/tests/` (single-writer package)
- Required levels: unit + property-based (fast-check) tests for every pure function and registry (P02-T03 ships these with the package); no integration tier — there is no I/O to integrate.
- Fixtures/builders: `packages/test-support/` and `packages/seed-data/` factories; never duplicated across modules; synthetic data only.

## Extension points

- New reason codes, entitlement names, units, or ID prefixes are added to the existing registries with tests; consumers regenerate/import, never copy (`just generate` for contract-facing values).
- A new feature flag is an entry in `registry/feature-flags.json`. A new person or role is an entry in `registry/owners.json`. Neither needs a code change. A new forbidden log word is an entry in `registry/forbidden-log-keys.json`, and every logger and lint that reads the file picks it up. A new word-split example is an entry under `forbidden` or `allowed` in `registry/forbidden-log-keys.examples.json`, and every matcher's tests that read the file check it. A new error-shape test vector is an entry under `vectors` in `registry/log-redaction.json`. A new correlation id test vector is an entry under `vectors` in `registry/correlation.json`. A new error code is an entry in `ERROR_CODES` (`errors.ts`; additive, the OpenAPI `ProblemDetails.code` is a pattern, not an enum).
