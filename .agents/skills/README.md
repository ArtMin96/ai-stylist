# Skills index

One `SKILL.md` per task type required by NFR-TEAM-100 (`planning/01-requirements-and-traceability.md`; doc 15 §12 points here). Each file has the six required sections — Trigger, Required reading, Workflow, Validation commands, Output, Stop / escalation — plus an Overlap note naming adjacent skills, `metadata.last-reviewed`, and a description with a negative trigger ("Not for … — use `<other>` instead"). Skills compose: run the producer skill first (contract, migration), then the consumer. Each skill is symlinked from `.claude/skills/<name>` so it is discoverable/preloadable; `CLAUDE.md` rules always apply on top.

`metadata.owner-agent` names who executes a skill: one or more agents from `.claude/agents/` (comma list), each of which preloads the skill through its `skills:` frontmatter, or `main-session` for a skill only the lead session can run. Every project agent also preloads [`agent-operating-contract`](agent-operating-contract/SKILL.md) (`user-invocable: false`): the base and worktree checks, the search-before-write commands, the stop conditions and the one hand-back report format. [`cross-platform-feature`](cross-platform-feature/SKILL.md) is `main-session` only: it is the entry point when a user asks for one feature on iOS and Android.

Overlap review (AC-9): each skill's Overlap section names its neighbours and the seam and ends with the paths it owns; no two skills own the same file set. The seams that were once claimed twice: `e2e/**` belongs to `e2e-device-testing` (`test-engineer`); the codegen scripts split as `tools/codegen/gen-swift.sh` → `ios-feature`, `tools/codegen/gen-kotlin.sh` → `android-feature`, `tools/codegen/gen-python.sh` → `media-ml-pipeline`, and the rest of `tools/codegen/**` → `tooling-ci`; `fashion-intel` belongs only to `fashion-intel-ingestion`; `apps/api/src/platform/**` adapters → `backend-module`; `apps/api/src/jobs/**` → `media-ml-pipeline`; `apps/api/src/modules/notifications/**` → `notifications-delivery`; `apps/api/src/modules/admin/**` → `admin-moderation`. `docs/modules/**` is shared between `docs-maintenance` and each module's skill, serialized by waves. The enforcement layer (`.claude/**`, `.agents/**`, `scripts/hooks/**`, `templates/**`) belongs to no skill or agent: the main session changes it with a human. Where a task crosses seams, the order is contract → migration → module → UI (iOS and Android in parallel, `cross-platform-feature`) → review → release.

Evals: every skill directory holds an `evals.json` (2–3 task prompts with assertions) and a `trigger-evals.json` (20 queries, 8–10 per side, negatives are near misses). Nothing scores them automatically yet; trigger accuracy is a manual step with the `anthropic-skills:skill-creator` workflow when a description changes.
