## Context

No cloud provisioning has happened yet: the Neon environments in P02-T07 are partial, `apps/api/src/trigger/` is a placeholder, and no Neon, Trigger.dev, R2, PostHog, RevenueCat or fal.ai SDK is declared in any package manifest (r7, "Why this decision should be made now"). The r7 audit (verified 2026-09-13) found that the app needs the _capabilities_ of most planned services but not most of the named vendors, and that the owner has the DevOps experience to run ordinary servers. Changing the vendor set now is materially cheaper than after the P02/P03 integrations. Store-fee and pricing claims that fed the unit economics (Google Play "10%") were also found to be wrong. This ADR records the consolidated baseline; product architecture (modular monolith + workers, ports, outbox, `StorageProvider`, `HolidayProvider`) does not change.

## Decision

Replace Trigger.dev Cloud, Railway, Neon, Cloudflare Images and the Nager.Date hosted API with **pg-boss v12 on the app database, owned servers + Docker + Coolify, self-managed PostgreSQL 17 + pgvector, worker-produced fixed derivatives on R2, and the embedded `date-holidays` library**; keep R2, PostHog Cloud, Grafana Cloud, RevenueCat, EAS (free allowance) and GitHub with explicit exit triggers.

Concretely:

- **Build:** `apps/api/src/jobs/` (pg-boss job definitions; workers run in the API process or a dedicated `jobs` process); P02-T08 = outbox relay + pg-boss + worker round-trip against the acceptance suite (kill/retry, idempotency, DLQ, replay, per-user cancellation, deletion/export scenarios); P02-T07 = self-managed PostgreSQL environments with pgBackRest PITR to an encrypted off-host bucket (R2), nightly `pg_dump`, PgBouncer, Grafana alerts; Coolify deploys with secrets synced from sops into Coolify environment variables; TLS to the database; host firewall; ephemeral/Testcontainers databases locally and in CI, staging migrations proven on a scratch database restored from the latest staging backup.
- **Configure:** private user media = presigned GET on the S3 endpoint (uncached, TTL ≤ 10 min); public app/content assets only (3D bundles, avatar/garment manifests, app content) = R2 custom domain with Cloudflare cache.
- **Forbid:** `@trigger.dev/sdk`, `TRIGGER_*`/`NEON_*` env keys, Railway project tokens, Cloudflare Images, `NagerDateHolidayProvider` as the production adapter, LLM wording polish of explanations in the product path (templates from reason codes only; any future NL polish needs a new doc-10 entry + eval), self-hosting FLUX.2 [dev] weights for commercial use (non-commercial licence — managed licensed endpoint only).
- **Evaluate, do not preselect:** self-hosted BiRefNet (MIT weights — never "rembg defaults", whose RMBG-2.0 weights are BRIA-licensed), Qwen3-VL (Apache-2.0) and SigLIP/SigLIP2 (Apache-2.0) as P06 eval arms; FASHN VTON v1.5 (Apache-2.0 code + weights) in the P11 gate; Open-Meteo managed vs self-hosted (AGPL-3.0; ≥ 8 GB RAM/100 GB disk, continuous ingestion) vs Apple WeatherKit REST in P08.

## Rationale

- Durable jobs are essential; Trigger.dev is not. pg-boss covers retry/backoff, DLQ, scheduling and concurrency on infrastructure that already exists, and the transactional outbox lives in the same database, so the T08 suite tests one consistency model. The fallback is gated on evidence, not preference.
- Railway hosted only portable containers. Coolify gives the same operational bar (reproducible deploys, health checks, rollback, environment isolation) on hardware the owner controls, at roughly the cost of the Railway line alone. The corrected fact that Railway private networking never included the external database removes the main argument for keeping it.
- The database holds the outbox, sensitive profile/closet state, recommendation snapshots and authoritative entitlements. Neon's real value was managed recovery, so the replacement is conditional on tested recovery, not on "Postgres in a container". The obligations are listed below and land in P02-T07 and the P14 drill; branch-per-PR is replaced by ephemeral databases and backup-restored scratch databases, which the migration tests already use.
- Cloudflare Images duplicated fixed derivatives the media workers already produce with lineage; R2's "built-in CDN" claim was incomplete (caching needs a custom domain; presigned private delivery is not cached), so the delivery model is now stated explicitly rather than assumed. Self-hosting the bucket is a larger obligation than running the API and is deferred.
- Holiday facts are low-criticality, cacheable context inputs; an embedded library removes an account, a network path and a key. Self-hosting Nager.Date was the r7 proposal, but its Docker image/NuGet package need a licence key, so the embedded library wins.
- Explanations already come from the decision trace by rule; the optional LLM polish added a paid provider on the critical path for no product requirement. Trend summarization in P12 keeps its LLM batch use.
- Open weights are not evidence of equivalence: the self-hosted AI arms join the existing gates (IoU/latency/cost, macro-F1/schema validity, replay) and are adopted only if they pass.
- Google Play's official table gives 10% service fee + 5% billing fee (15%) for Play-billed auto-renewing subscriptions in the EEA/UK/US program from 2026-06-30 and 15% elsewhere, so the 15% base case stands and the "reportedly 10%" note was wrong ([Google Play service fees](https://support.google.com/googleplay/android-developer/answer/112622), as of 2026-09-13).
- Hypotheses, labelled: "pg-boss sustains ≤ ~10 jobs/s on the app database" (A11) and "one host meets API p95 budgets at launch" (A12) are assumptions validated in T08 and P14 load tests, not measurements.

## Consequences and revisit triggers

- Positive: three vendor accounts (Neon, Railway, Trigger.dev) and one paid transform product removed before any integration existed; launch infra envelope becomes one owned server (~€10–25/mo class) + R2/PostHog/Grafana free tiers; reduced vendor concentration (RISK-11); fewer secrets; the outbox and the queue share one transactional store; no network dependency for holidays.
- Negative/accepted debt — **database recovery obligations the owner now carries (RISK-17, P02-T07 + P14 drill):** WAL archiving + PITR via pgBackRest to an encrypted off-host bucket; nightly `pg_dump` logical backup; PgBouncer pooling; disk/replication/backup-age alerts in Grafana; a **quarterly restore drill with recorded evidence**; encryption at rest via host disk encryption + TLS in transit; major-version upgrades and patching; moving to a dedicated DB host once load justifies. Also: host patching, capacity monitoring and availability for the API/workers; PostgreSQL hosts the queue, so queue load competes with OLTP load; CC-BY-3.0 attribution for holiday data; the private-media delivery path is uncached by design.
- **Revisit when:**
  - the **P02-T08 acceptance suite fails on pg-boss** (kill/retry, idempotency, DLQ, replay, per-user cancellation, deletion/export) → self-hosted Trigger.dev (new DEC);
  - **measured queue volume** approaches the A11 assumption (~10 jobs/s sustained) or queue latency violates job budgets → dedicated queue host or workflow engine (new DEC);
  - **PostHog Cloud or Grafana Cloud reach their paid threshold** (before any paid usage) → self-host PostHog OSS only if in-house data is itself a requirement; self-hosted Grafana stack on a separate failure domain;
  - **RevenueCat approaches $2.5k MTR** → reassess direct StoreKit 2 / Play Billing, adopted only after the full replay/reconciliation matrix passes;
  - **OQ-07 residency** rejects the chosen server region or PostHog's region → move host/region, self-host analytics;
  - a restore drill fails or backup-age alerts fire unresolved → stop feature work until recovery is proven again (RISK-17 kill criterion);
  - hosting ops load proves too high for the team → managed PaaS fallback (new DEC).

  Reversal of any item requires a new DEC entry.
