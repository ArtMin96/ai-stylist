## Context

Until now the client was one React Native + Expo app (`apps/mobile`, Expo SDK 57, RN 0.86.3; DEC-04, DEC-38). The 3D avatar surface depended on `react-native-filament` (DEC-05), and iOS builds were planned on EAS Build or a GitHub Actions macOS runner (DEC-30, OQ-04, ADR-0002). On 2026-09-22 the product owner decided to drop React Native and Expo and to build fully native apps in this monorepo: Swift/SwiftUI in `apps/ios/` and Kotlin/Jetpack Compose in `apps/android/`. Both apps talk to the one backend through the OpenAPI 3.1 contract in `packages/contracts`. The foundation code for both apps has landed on `chore/native-foundations`: the home screen at parity with the retired RN screen, generated API clients, a consent-gated analytics port, strict compiler and lint settings, and `.github/workflows/ios.yml` + `android.yml`.

What forced the decision now:

- **The product owner prefers native** UI toolkits and first-party tooling.
- **The 3D wrapper had gone dormant.** `react-native-filament` was RISK-01, the top-ranked risk. Its last release was 1.11.0 on 2026-05-27, and it had had no commits for 16 weeks. Its CI was pinned to RN 0.83.1, and nothing showed support for RN 0.86 / Expo 57. Margelo, its maintainer, was acquired by Callstack on 2026-09-01. (Evidence gathered in the 2026-09-22 session from the project's release and commit history. It was not re-verified for this ADR.)
- **Platform refreshes need first-party tooling.** On 2026-09-22 EAS could not build against the iOS 27.1 SDK. The iPhone Duo (announced 2026-09-09, ships 2026-10-23) needs an iOS 27.1 SDK rebuild and new APIs.

## Decision

We build fully native clients: **Swift 6 + SwiftUI at `apps/ios/`** (XcodeGen `project.yml`, local SwiftPM packages, generated `.xcodeproj` gitignored) and **Kotlin + Jetpack Compose at `apps/android/`** (its own Gradle root with `build-logic/` convention plugins). Both stay in this monorepo and share the backend through the OpenAPI 3.1 contract. React Native, Expo, EAS and `apps/mobile/` are removed.

Concretely:

1. **Clients are generated from the contract, committed, and never edited by hand.** The Swift client lives in `packages/contracts/gen/swift-client/` (swift-openapi-generator 1.13.1, `tools/codegen/gen-swift.sh`). The Kotlin client lives in `packages/contracts/gen/kotlin-client/` (openapi-generator 7.25.0, `tools/codegen/gen-kotlin.sh`). Both are deterministic and covered by `just generate --check`. The TS client stays, because `apps/api` consumes it.
2. **Safety settings are part of the decision, not a preference**, because they are how a team new to Swift and Kotlin gets review help from the compiler:
   - iOS: Swift 6 language mode, complete strict concurrency, main-actor default isolation, warnings as errors, SwiftLint + swift-format safety rules, and a ban script (`@unchecked Sendable`, `nonisolated(unsafe)`, `@preconcurrency import`, UI imports in `Core`, generated-client imports outside `APIData`) with fixtures that prove each ban fires.
   - Android: Kotlin `allWarningsAsErrors`, Android Lint `warningsAsErrors` + Slack compose-lint-checks, Spotless/ktlint, detekt (limited rule sets), a module-graph allow-list (`checkModuleGraph`), and committed dependency lockfiles + `verification-metadata.xml`.
3. **No 3D in the native apps now.** When 3D resumes, the plan is **Google Filament's C++ engine used directly on both platforms**: Metal on iOS, the official Android AARs, with glTF + KTX2 + Draco and up to 256 morph targets. That keeps DEC-06/DEC-07 unchanged. RealityKit is rejected for the avatar path: it is USDZ-only, and the converters decode Draco and flatten KTX2. SceneKit is dead. The renderer-agnostic asset pipeline (`assets/3d`, `just assets-validate`, `prototype/g3-filament-spike`) stays.
4. **iOS delivery:** the GitHub Actions macOS runner (`xcode-27` image today) is the only CI lane for iOS. EAS is removed. iOS development needs a Mac, and the team has one (supersedes DEC-03's "no Mac").
5. **Toolchain:** Xcode 27.0 / Swift 6.4 (iOS deployment target 26.0); AGP 9.3.3 / Gradle 9.7.1 / Kotlin 2.4.20 (compileSdk 37, targetSdk 36, minSdk 29). **JDK moves from Temurin 17 to 21**, which AGP 9 and Robolectric for SDK 36+ need. Watchman is dropped.
6. **Shared conventions:** bundle id / applicationId `app.aistylist.mobile` (`.dev`, `.preview` suffixes), environments dev / preview / prod, a host-only `API_BASE_URL`, and one Maestro flow at `e2e/smoke.yaml` for both apps.
7. **Product scope is unchanged.** MVP is still A1 + G0 + G2. There are no garment meshes in v1, and DEC-07/08/09 stand. The A1 renderer is deferred, and the UI stack does not affect it.

## Rationale

Option A is chosen because the product owner prefers native, and because the evidence moved against B: RISK-01's trigger (a dormant wrapper with no path to the current RN/Expo) was effectively met, and EAS could not target the newest iOS SDK. Option C would have made the team learn native code anyway, while keeping RN's structural gaps.

The framing needs to be honest. **Native does not adapt to new form factors for free.** The iPhone Duo still needs an SDK rebuild and adoption of new APIs. What native gives us is a same-day path to those SDKs, system refreshes on recompile, and first-party adaptive components, widget/Live Activity surfaces and scene support. RN either cannot express these or adopts them late. KMP (D) is rejected _for now_ because Swift Export is still Alpha. Flutter (E) was rejected earlier for the same reasons it still fails.

The price is two UI codebases maintained by a small team that is new to both languages. The strict settings in Decision item 2, the generated clients, the tests, and the parity review (RISK-19) are the mitigation. The team intends to build real Swift and Kotlin review competence, not rely on the tooling alone (RISK-18, ASM-11).

## Consequences and revisit triggers

- **Positive:**
  - RISK-01 and ASM-01 are retired. OQ-04 is resolved.
  - Each platform gets first-party SDK adoption.
  - Compiler-enforced module boundaries: SwiftPM target dependencies and the Gradle module graph.
  - The lockfile roughly halved when `apps/mobile` was removed.
- **Negative / accepted debt:**
  - Every client feature is built and reviewed twice.
  - Review capacity is the main risk (RISK-18).
  - iOS work needs the team's Mac, and the macOS runner is a single CI lane (RISK-12 amended).
  - The `xcode-27` runner image is still marked preview.
  - Shared-kernel constants (reason codes, entitlement names, units) have **no language-neutral emission yet**. Native code cannot import TypeScript, so the "never copy constants into clients" invariant is only met for what the contract carries (OQ-15).
  - The contract's `servers[]` URLs end in `/v1` and its paths also start with `/v1`. Both clients work around this with a host-only base URL (OQ-16).
  - Preview builds point at the production API host until a staging host exists (OQ-17).
  - Release signing and store upload lanes (TestFlight, Play) are not built yet (OQ-18).
  - Planning docs written for RN keep one-line historical notes where their content was an RN-specific research conclusion.
- **Revisit when:**
  - Parity drift or review backlog blocks a phase exit twice in a row (RISK-18/19 kill criteria). Re-evaluate shared-logic options then (KMP once Swift Export is stable, or a thin shared core).
  - Kotlin's Swift Export reaches Stable.
  - A 3D requirement cannot be met by Filament C++ on either platform.

  Reversal requires a new DEC entry.
