## Context

Neither app has a brand theme. Android wraps everything in the stock Material 3 `lightColorScheme()` / `darkColorScheme()` (`apps/android/app/src/main/kotlin/app/aistylist/app/ui/theme/Theme.kt`, commented "Brand colors land with design"), and iOS uses SwiftUI system defaults. Brand v1 now has its inputs. DEC-85 sets the name Garderi with a lowercase `garderi` wordmark. The logo is P2 Garden Viridian. The colour schemes are S1 Garden Light, S2 Garden Dark (the default) and S7 High Contrast, all on the Claude Design canvas "Garderi Colour Schemes" (https://claude.ai/artifact/Db28dfjbyvJgksMQFrXhVA). The screens are drawn on the canvas "Garderi App UI" (https://claude.ai/artifact/3PfhQn2y9YKXtBz2fc1GeE), whose pages are: 1 Overview, 2 Foundations, 3 Components C01–C10, 4 Wireframes, 5 earlier key screens, 6 All screens SC01–SC15, 7 Prototype P01–P18, 8 Avatar/selfie/try-on and 9 Design rules R1–R6. `CLAUDE.md` requires a single source of truth for shared values and forbids copying them into the iOS and Android apps. Design tokens have no home yet, so the first themed screen on either platform would hard-code them twice. The owner also asked for a setup in which developers without UI experience cannot drift from the design: a UI agent that every agent consults, and a prototype before any new screen or element is coded.

## Decision

`DESIGN.md` at the repository root, in its YAML frontmatter, is the single master for design tokens (colours, typography, spacing, radius, elevation, motion), and impeccable is adopted for its commands only. In detail:

1. **Tokens.** `DESIGN.md` follows impeccable's DESIGN.md format. Its token values equal the canvas rule R2 values. When the two disagree, the owner settles it on the canvas, then `DESIGN.md` is updated to match.
2. **Generated native theme (follow-up).** A `just generate` step will emit the iOS and Android theme code from `DESIGN.md`, and `just generate --check` will fail CI on drift. It is not built by this ADR. Until it lands, feature UI must not hard-code any colour, font size, spacing or radius value; it uses the future design-system module.
3. **impeccable.** The user-scope plugin (v4.6.0) is used for its commands: `init`, `document`, `shape`, `critique`, `audit` (native), `adapt` (native) and `polish`. Its automatic hooks are off in this repository, for two reasons. Its detector scans web files only, and both apps are native Swift and Kotlin. It also downloads an engine binary, which nothing in the repository pins or scans.
4. **Product brief.** `PRODUCT.md` at the repository root is made with `/impeccable init` (platform `adaptive`) and derived from `planning/SPINE.md`. SPINE wins on any conflict, and `PRODUCT.md` says so at its top.
5. **Visual reference.** The "Garderi App UI" canvas is the visual source of truth. "Garderi Colour Schemes" is the source for colours and the logo.
6. **Ownership and gate.** A new `ui-designer` agent owns `DESIGN.md`, `PRODUCT.md`, `.impeccable/**` (`docs/**` stays with `docs-maintainer`), and never writes app code. A new `ui-prototype-first` skill is the gate for every new screen or UI element: check `DESIGN.md`, the canvas and the existing surface briefs; prototype on the canvas in light and dark, built only from components C01–C10; get the owner's approval (dated in the brief); write the surface brief in `.impeccable/surfaces/<screen>.md`; the engineer builds with tokens only; `ui-designer` reviews the code and screenshots; fix; merge. Screens already drawn on canvas pages 6 and 8 count as prototypes once the owner approves them.

## Rationale

A is the only option with one platform-neutral master that both agents and the design tooling can read. B gives two hand-kept masters, which is the duplication `CLAUDE.md` forbids. C fits the generator but not the content. Tokens come with prose rules (contrast, states, honesty copy), and impeccable reads neither from a kernel JSON. C stays compatible as a later step: if token generation moves into the kernel generator, the parsed frontmatter can be emitted through the ADR-0005 path without changing the master. D leaves review to each agent's habits, which is the drift the owner wants to prevent. The hooks are off because they would do nothing useful here (no web files) and would fetch an unpinned binary on every session.

## Consequences and revisit triggers

- Positive: one file answers "which token?" for every agent. New screens go through a prototype and owner approval before any code is written. Review against `DESIGN.md` and the surface brief replaces taste. The path to generated, drift-gated native themes is fixed before the first themed screen.
- Negative/accepted debt: until the generator and lint bans land, drift between `DESIGN.md`, the canvas and native code is caught only by `ui-designer` review. The canvas lives on claude.ai, outside the repository, so its history is not in git. The DESIGN.md format belongs to a third party.
- Engineering follow-ups (recorded, not built):
  1. An iOS design-system target in `apps/ios/Packages/Features` (SwiftUI is not allowed in the Core or `*Model` targets).
  2. An Android `:core:designsystem` module (an entry in `settings.gradle.kts` and in `ALLOWED_MODULE_EDGES`).
  3. A `just generate` step that emits the tokens from `DESIGN.md`, with the `--check` drift gate.
  4. Lint bans on literal colours and sizes in feature UI (a SwiftLint custom rule, a detekt rule, or the banned-pattern check).
  5. Screenshot tests.
  6. A contrast lint on the tokens (doc 13).
- Security: the impeccable plugin is installed at user scope, not in the repository. Its engine binary sits outside the repository's dependency, licence and security-scan policy (`just security-scan` does not see it). With the hooks off, the binary does not run automatically in this repository. Customer data, photos and anything else classed as sensitive must never be passed to its commands.
- **Revisit when:** the generator cannot express a token type the DESIGN.md format needs; impeccable changes the DESIGN.md format in a breaking way or stops being maintained; its hooks gain native (Swift/Kotlin) support without a downloaded binary; or drift is found in merged code twice before the lint bans land. Reversal requires a new DEC entry.
